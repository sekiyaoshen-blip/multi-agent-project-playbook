# Multi-Agent Model

[English](README.md) | [安装说明](INSTALL.zh-CN.md)

保留长期模块归属，减少协作负担的 Codex skill。只在初始化、精简、修复或升级
项目协作方式时调用，不要每做一个功能都加载。

## 默认怎么工作

- 简单功能、页面或修复：沿用现有技术栈，直接实现、相关验证、交付，满足验收即停止。
- 单任务项目：简短的 AGENTS.md 足够。
- 稳定的多模块项目：增加归属登记表，复用长期显性模块任务；任何任务都能直接转派给实际负责人。
- 跨模块工作：一个牵头任务、互不重叠的范围，只对齐本次实际需要的共享接口。
- 临时子智能体：处理负责人范围内值得并行的独立工作，不替代已有模块负责人。
- 临时进度和结果：留在原生任务或已有工作看板中，不再复制一套文件日志。
- 长期事实：只在发生变化时更新现有文档中的对应位置。

优先使用当前可用的原生检索、消息、等待、结果读取、分支任务和交接能力。
创建新的显性任务仍需要用户明确授权。

## 不再默认做什么

不再自动创建 PRD、架构文档、status/handoff/runbook 全家桶、派单表、
哈希台账、锁、独立验收任务和回传文件。已有项目要求和本次改动涉及的
具体高影响风险仍然保留，不把“精简”理解为取消必要保障。

[能力适配说明](references/codex-native-notes.md)记录了 2026 年 3 至 9 月
Codex 更新和 GPT-6 Astra 提示词行为对本次精简的影响。
不包含模型选择、供应商路由或降级策略。

## 最小项目模板

`project-skeleton/` 是按需选取的模板，不是全部复制：

```text
AGENTS.md                       项目入口
docs/thread-registry.md         有稳定模块任务才需要
docs/current-work.md            缺少共享工作面时才需要
```

优先复用已有文档和工作看板。详细协作规则、产品/技术设计和恢复模板只在
确有需要时从 references 选取。升级 skill 不会自动改写所有旧项目。

## 与个性化指令分工

[中文全局偏好示例](references/personal-instructions.zh-CN.md)负责语言、简洁交付、
适度测试、Git 边界及沿用现有提交部署路径。项目 AGENTS.md 只负责模块归属
与协作，不重复整段个人偏好。

安装 skill 不会隐式修改个人设置。只有用户明确要求时，才把偏好应用到
受支持的全局 AGENTS.md，并与已有内容合并。不要在多个设置入口同时保留
互相矛盾的旧版和新版规则。
